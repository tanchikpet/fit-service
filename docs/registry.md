# Реестр сайтов FIT SERVICE

Открыть: https://tanchikpet.github.io/fit-service/registry.html

## Добавление и редактирование

1. Нажмите «Подключить GitHub».
2. Создайте fine-grained personal access token в https://github.com/settings/personal-access-tokens/new только для репозитория `tanchikpet/fit-service`.
3. Дайте Contents: Read and write. Для кнопки «Проверить и найти адреса» также нужны Actions: Read and write. Установите срок действия токена.
4. Вставьте токен в форму. Он хранится только в памяти текущей вкладки, не в localStorage, не в файлах GitHub и не передается сторонним сервисам. После обновления страницы подключение нужно повторить.
5. Используйте «Добавить страницу» или «Редактировать». Сохранение создает коммит в `data/registry.json`; доступ к записи проверяет GitHub.

При конфликте изменений редактор не перезаписывает чужую версию. Скопируйте свои поля, закройте форму, обновите страницу и повторите. Исходные 286 строк сохранены, включая дубликаты из исходного списка. Новые записи с совпадающим адресом редактор отклоняет.

## Заявки FIT Requests

В форме заявки есть раздел «Страница сайта»: действие (новая/закрытие), планируемый и фактический адреса, назначение, ответственный, срок акции, адрес редиректа при закрытии. Проект выбирается в общем поле проекта.

После сохранения такой заявки предлагается подключить GitHub. Только поля страницы, ID, название, проект и статус записываются в `data/page-requests.json`; остальные задачи прототипа остаются в локальном браузере. Отмена подключения оставляет заявку локально, но не сохраняет в GitHub. В карточке можно повторить сохранение. В списке заявок кнопка «Загрузить из GitHub» позволяет открыть сохраненные заявки на другом устройстве.

У готовой заявки появляется «Добавить в реестр» или «Перенести в архив». Это отдельное явное действие. Требуется фактический URL. Для закрытия также нужен адрес назначения редиректа; закрываемый URL должен уже существовать в реестре. Запись о редиректе в реестре **не настраивает редирект на сервере лендинга**.

Репозиторий публичный: поля реестра и сохраненные поля заявок будут доступны всем читателям репозитория. Не добавляйте пароли, токены или закрытые клиентские данные в описания.

## Проверка известных адресов и поиск

Workflow `.github/workflows/registry-monitor.yml` запускается ежедневно в 05:00 UTC (12:00 Новосибирск), а также вручную через кнопку редактора или Actions → Registry monitor → Run workflow. GitHub может запускать расписание с задержкой.

Проверки выполняются на GitHub Actions, поэтому CORS лендингов не мешает. Записываются HTTP-код, фактический конечный адрес, изменение назначения относительно предыдущей успешной проверки и несовпадение с указанным в реестре редиректом. Шаблоны URL не проверяются. Недоступность, 403 и ошибка DNS не меняют архивный статус записи.

Новые кандидаты собираются из ссылок известных страниц, sitemap.xml и публичных сертификатов для fitauto.ru, fitavto.kz, fitautolab.ru. Отсутствие результатов из одного источника не останавливает другие; ошибки источников сохраняются в отчете. Автоматического перебора имен поддоменов нет. Ссылки с query-параметрами и файлы изображений/документов отсекаются. За один запуск добавляется до 1500 новых кандидатов. Список не гарантирует обнаружение всех страниц и поддоменов.

Откройте «На проверку»: «Добавить в реестр» открывает форму с найденным URL; заполните проект и назначение. «Пропустить» сохраняет отклонение, адрес не появится заново. Подтвержденные адреса не добавляются повторно при следующих запусках.

Отчет: `data/registry-checks.json`, кандидаты: `data/registry-candidates.json`. Редактор читает актуальные данные из GitHub API; результаты автоматических коммитов доступны даже без повторной сборки GitHub Pages. API имеет лимиты; при ограничении доступен понятный текст ошибки.

## Почтовые напоминания: настройка владельцем

Отправка по умолчанию не подключена. Нужно выбрать адрес получателя и почтовый сервис. Не отправляйте SMTP-пароль в чат и не добавляйте его в код.

Откройте https://github.com/tanchikpet/fit-service/settings/secrets/actions и создайте Repository secrets:

| Имя | Значение |
| --- | --- |
| `ALERT_EMAIL` | Адрес получателя напоминаний |
| `SMTP_HOST` | SMTP-сервер вашего почтового сервиса |
| `SMTP_PORT` | 465 для SSL или 587 для STARTTLS (по умолчанию 465) |
| `SMTP_USER` | Имя пользователя почтового сервиса |
| `SMTP_PASSWORD` | Пароль приложения или SMTP-пароль |
| `SMTP_FROM` | Разрешенный сервисом адрес отправителя |

Напоминания приходят за 7, 3, 1 день, в день окончания, а также один раз при обнаружении пропущенного срока в течение следующих 7 дней. В письме перечислены конкретные URL, дата окончания и ответственный. Архивные записи исключаются. Отметка об отправке сохраняется только после успешного SMTP-ответа; повторных ежедневных писем для одного этапа нет. При смене даты акции отсчет начинается заново. Возможна повторная доставка, если отправка прошла, а последующий коммит отчета завершился ошибкой.

Проверьте Actions → Registry monitor: в Summary указан результат отправки или сообщение «Почта не подключена». После ввода secrets выполните Run workflow. Успешная сборка сайта сама по себе не означает, что почта настроена.
