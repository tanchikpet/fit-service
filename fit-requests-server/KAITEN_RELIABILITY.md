# Техническая приемка синхронизации WEB

## Исходные данные и границы проверки

На 28.11.2026 интерфейс показал 1007 карточек, 1006 доступных историй, 5785 перемещений, 4408 записанных авторов и 815 карточек с отметкой проверки авторов. По чек-листам было 23 успешных результата и 984 ошибки. Остальные семь карточных источников показали по 1006 успехов. База занимала 26 МиБ, дополнительные таблицы 4 МиБ. Это данные пользовательской приемки. Подключения только для чтения к production PostgreSQL и рабочего токена API в среде разработки нет. Повторный проход по production не выполнялся.

| Вопрос | Что установлено | Что подтверждать по production |
|---|---|---|
| 984 ошибки чек-листов | Старый загрузчик записывал ошибку без HTTP-статуса, если `checklists` отсутствовал или был `null`. Пустой массив записывался как пустой успешный результат. Та же ветка без статуса могла возникать по другим причинам, например из-за формата элементов. Документация детальной карточки описывает массив и допускает `null` у вложенных `items`. Новый загрузчик выделяет недоступное поле отдельно (запись `error` с HTTP 200), сохраняет предыдущий успех, оставляет 403/404 самостоятельными исходами. | Сверить таблицу исходов и выполнить ограниченную выборку ответов на карточках из когорты. Конкретный смысл отсутствующего ключа и `null` под рабочим токеном пока не подтвержден. |
| 815 карточек и 4408 авторов | Завершение прежнего этапа означало исчерпание критериев выбора текущего прохода, в том числе с отсечкой по времени предыдущей попытки. Наличие отметки на карточке не означает, что ответ включал каждое ранее сохраненное событие. 192 карточки и 1377 событий являются разными единицами учета. | Сопоставить карточки с отметками, ошибки и покрытие по отдельным событиям. В отчете есть повторяющиеся ID связей, ссылки на себя и цели за пределами сохраненной выборки. | Проверить счетчики в WEB. Цель за пределами выборки может быть недоступной или находиться в другом пространстве. |

Когорта исправления чек-листов выбирает старые ошибки без HTTP-статуса и обрабатывает до 24 карточек за проход. Успешные карточки и уже классифицированные ответы HTTP 200 из этой когорты исключаются. Для авторов выбираются карточки с сохраненными событиями без автора и без индивидуальной отметки наблюдения. Каждый полученный ID сопоставляется с событиями PostgreSQL. Отдельно учитываются заполненные авторы, явное `null`, отсутствие поля, непроверенные события и неуспешное чтение. Ответ, в котором не пришел конкретный ID старого события, не меняет его наблюдение. Старый автор сохраняется.

## Наблюдения и аналитика

- Отчет показывает заполненность основных полей, покрытие и состояние отдельных источников, типы и текущие доски, а также распределение числа карточек на участника без имен. Для RR Приоритета 428033 показываются заполненность и распределение по году создания в НСК, текущей доске и типу. Отсутствующее значение остается отдельным. Текущий справочник WEB из приемки содержит 218940 High, 218941 Medium, 218942 Low. Прежняя оценка заполненности 510 карточек относится к диагностической выгрузке.
- Версии досок, колонок и дорожек используют существующие интервалы наблюдений. При синхронизации учитываются доступные конфигурационные поля в разрешенном списке. Снимки карточек отслеживают сроки, оценки, тип, приоритеты, участников, родителей и детей, блокировки, чек-листы и расположение. Изменение снимка хранится один раз с датой обнаружения. Первый снимок задает базу, `event_at` остается пустым. Изменение, отмененное между двумя чтениями, может остаться незамеченным.
- Загрузка перемещений сохраняет исходное время и идентификатор Kaiten. Ограниченная проверка активности продолжает работать с ID при отсутствии раскрытых объектов в ответе после 01.12.2026. Для восстановления изменений в 2025 и 2026 годах нужны результаты пагинации по отобранным действиям и пригодные предыдущие и новые значения. Само наличие события назначения, снятия ответственного или связи в выборке не доказывает непрерывную историю. Массового чтения активности и автоматической интерпретации действий в этом PR нет.
- Достоверно доступны состав сохраненной выборки, число созданных карточек, наблюдаемые поступления и перемещения и текущие распределения с показателями полноты. На основе загруженных данных нельзя выводить число фактически выполненных задач, KPI, соблюдение сроков и исторические распределения трудозатрат. Перенос 522 карточек остается зарегистрированными перемещениями. Колонки 3189877, 3189965, 3189878, 3189992 и 3189879 доски 898832 требуют подтверждения назначения и периода владельцем процесса.

## Политика обновления

Штатная синхронизация основных карточек сохранена. Условие `updated_after` документировано, но документация и локальные тесты не показывают, какие операции во внешних методах гарантированно повышают версию карточки. Комментарии, чек-листы, связи, блокировки и участники поэтому участвуют и в ограниченной сверке по возрасту. Порог сверки составляет 14 суток, но из-за лимита 24 карточки в сутки обход 1007 карточек занимает около 42 суток при полной очереди и отсутствии повторных ошибок. Интервал нужно уточнить после фактических замеров WEB. Для истории установлен порог сверки 30 суток и лимит 48 карточек на фазу. Автор по новым движениям читается одновременно с перемещениями.

Проход ежедневно открывается в 06:00 НСК. Внутри прохода партии продолжаются с минутным интервалом и хранят контрольную отметку в PostgreSQL. Успешно обработанные записи пропускаются при возобновлении. HTTP 403/404 выделены и для карточных источников повторно проверяются через 30 суток. Временные ошибки и 429 ограничены повторными попытками, после которых долгий `Retry-After` откладывает следующую партию. Систематические отказы в доступе требуют вмешательства администратора. Лимит 90 запросов на партию дополнительных источников, по 6 карточек на партию. Для истории до 12 карточек и до четырёх попыток на запрос. Теоретическая граница за проход составляет 90 + 2 × 4 × 12 × 4 + 3 × 4 × 90 = 1554 вызова с учетом повторов. Обычная нагрузка зависит от изменившихся карточек и пагинации справочников. Увеличивать лимиты до замеров не следует.

Проверяются размер базы с индексами, объем таблиц наблюдений, лимит существующих enrichment-таблиц и число активных подключений. `pg_database_size` не измеряет свободное место тома Railway и не включает весь WAL. Перед включением расписания лимит `KAITEN_SYNC_DATABASE_LIMIT_BYTES` задается по метрикам тома с резервом на WAL, другие данные и рост. При достижении порога сбор приостанавливается.

## Порядок выпуска

1. Получить отдельное согласование выпуска, применения миграции и включения расписания. Зафиксировать текущий деплой Railway, размер тома и запас места.
2. Выпустить версию приложения с отсутствующей или выключенной `KAITEN_SYNC_DAILY`. По существующему маршруту аналитики проверить контрольные агрегаты в техническом разделе. Сверить с приемкой и сохранить агрегаты вне production.
3. Применить только `migrations/003-kaiten-reliability.sql` выделенным авторизованным способом. Миграция отсутствует в цепочке запуска приложения. Она транзакционная и повторяемая, содержит короткие ограничения ожидания блокировки и времени команды. На событиях требуется краткий `ACCESS EXCLUSIVE`, добавляемые колонки допускают NULL и не имеют значений по умолчанию. Обратный выпуск приложения допускается с сохранением новых таблиц и колонок. Независимой копии production нет.
4. Проверить фоновый ручной контрольный проход из admin-раздела при утвержденном лимите базы. Сравнить исходы чек-листов, авторов и ошибки до и после. Проверить штатную синхронизацию и нагрузку по Railway Metrics.
5. Включать расписание отдельным согласованным изменением `KAITEN_SYNC_DAILY=true`. Для остановки новых автоматических проходов отключить настройку, а для отката приложения вернуть предыдущий деплой. Завершенная партия сохраняет результаты. DDL отката не требуется.

Если действующий доступ к PostgreSQL по-прежнему ограничен телефоном, перед применением миграции потребуется согласовать существующий защищенный канал для выполнения этого фиксированного SQL. Этот PR не предоставляет общую консоль PostgreSQL и не добавляет административное применение 003.
