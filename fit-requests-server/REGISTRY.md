# Реестр сайтов на Railway

Маршрут `/app/registry`, единая авторизация FIT Requests. Чтение доступно приглашенным пользователям, запись/кандидаты/запуск проверки — только роли admin (PM). Все изменения требуют same-origin POST; пароль или GitHub token в браузере не нужны.

## Перенос

При первом запуске initRegistry одной транзакцией импортирует seed из main: 286 записей, 463 кандидата, 293 результата проверок. Метка migration-v1 предотвращает повторный импорт. Исходные ID, архив, шаблоны, дубли исходного реестра сохраняются. История отправленных напоминаний перенесена без зашифрованной привязки старого бота. Файлы seed — только первоначальная загрузка, PostgreSQL является источником текущих данных.

Запись проверяет revision и сохраняет журнал изменения. Добавление кандидата и создание записи — одна транзакция. Ошибка оставляет форму открытой. Новые одинаковые адреса отклоняются; существующие дубли не удаляются.

## Проверки и уведомления

Python scanner запускается сервером, пишет промежуточные файлы во временный каталог. Итоги переносятся в PostgreSQL; конкурентные изменения записей и отклонения кандидатов не перезаписываются. Advisory lock исключает параллельные запуски. Таймаут сканирования — 20 минут. При ошибке автоматический повтор не чаще чем через 30 минут.

Сохранены HTTP-коды, конечные адреса, изменения редиректов, ссылки со страниц, sitemap и поиск по сертификатам. Проверяются только публичные HTTP(S) адреса на стандартных портах. DNS-адрес проверяется и закрепляется на время соединения, каждый редирект проверяется отдельно, TLS проверяется. Архивный статус не меняется автоматически. Ошибки отдельных источников показываются в отчете.

Планировщик проверяет расписание каждую минуту: раз в день начиная с 12:00 Asia/Novosibirsk; после простоя выполняет пропущенный запуск в этот день. Ручной запуск доступен PM. PostgreSQL сохраняет отчет и отметки уведомлений между деплоями.

Напоминания идут существующему TELEGRAM_ADMIN_ID через TELEGRAM_BOT_TOKEN текущего бота FIT Requests: за 7, 3, 1 день, в день окончания и один раз в первые 7 дней просрочки. Архив исключен. Отметка ставится после подтверждения Telegram; при аварии между доставкой и записью возможен повтор. Старый GitHub workflow нужно отключить при переключении, иначе два процесса могут отправлять напоминания.

Dockerfile включает Python 3 и Node 22. Не добавлять .env, node_modules или ключи в образ.

## Проверка

`npm test`: валидация, права записи, сроки напоминаний и существующие тесты авторизации/Kaiten. Дополнительно проверены импорт дважды, запись/архив, конфликт revision, дубли, прием кандидата на PGlite (PostgreSQL), интерфейс PM/сотрудника через jsdom. PGlite-проверка не моделирует advisory locks и конкурентные соединения production.

Передача полей заявок в Kaiten и обработка ошибок сохранения заявок в этот перенос не включены — отложены пользователем.
